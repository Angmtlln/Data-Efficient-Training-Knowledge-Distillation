# Эксперимент: длинные и нестабильные фразы

## Вопрос

Улучшает ли небольшая доля фраз с ненулевым held-out forgetting качество ModernBERT по сравнению со случайными длинными фразами той же метки и группы длины?

## Протокол (зафиксирован до обучения)

- Основа: закрепленный SST-2 snapshot серии 01 (`dataset_spec.json`): pool 65 349, val 2 000, GLUE validation как тест 872. Доступны метки всего пула; 10% — бюджет обучения target, не общий бюджет разметки.
- Модель `answerdotai/ModernBERT-base`, фиксированная ревизия из серии 01, 3 эпохи, batch 32, lr 5e-5, warmup 6%, weight decay 0.01, max length 64; эпоха выбирается по val accuracy.
- Индексы 6534 строк на поднабор, score seeds и selection seeds 17, 42, 101; планируемые training seeds такие же, по одному на выборку. Дополнительные сids обучения позволят отдельно измерить вариацию модели и выборок.
- Четыре условия: `random`; `len8` (случайные из текстов не менее 8 слов, счёт через `str.split`); `len8_matched_random`; `len8_forgetting`.
- Для каждой пары выбираем 327 длинных строк с ненулевой оценкой forgetting (сначала более высокая оценка, случайное разрешение равенств). Строим контрольные замены нулевого скора в тех же группах метки и длины: 8–11, 12–15, 16–19, 20–23, 24–27, 28–31, 32+ слов. Остальные 6207 строк — общий случайный фон среди длинных фраз, исключая выбранные 327 кандидатов и их замены. Другие строки с ненулевым скором могут случайно попасть в общий фон. Контроль сравнивает именно заменяемые строки; это не простая безусловная выборка `len8`.
- Оценки вычислены ранее в серии 01: 3-fold TF-IDF + SGD log-loss, 8 эпох, переходы от правильного ответа к ошибке на данных вне обучения соответствующего proxy. Фиксированные исходные score-файлы и hash пула проверяются; оценка каждого сида соответствует той же серии proxy. Это не оценка забывания самой ModernBERT и не точная реализация оригинального forgetting.
- Основное исследовательское сравнение — парная разница test accuracy `len8_forgetting` минус `len8_matched_random`; также accuracy, macro F1, F1 положительного класса, поведение на val, повторяемость и стоимость. Оценка на 872 строках уже многократно использовалась командой, независимого подтверждения нет.
- Прокси и отбор идут сверх целевого обучения, прокси на этот раз переиспользован; учитывать историческую стоимость и не заявлять полное ускорение только по времени target.
- Все 12 выборок, их контрольные суммы, аудит состава, предсказания и метрики сохраняются. Смена сидов данных и обучения связана; 3 пары — пилот для гипотезы, а не подтверждение малых эффектов.

## Запуск

Установить зависимости из `requirements.txt` и подходящий PyTorch. Из корня репозитория:

```bash
python experiments/01_cpu_selection/code/download_data.py
python experiments/01_cpu_selection/code/tokenize_data.py
python experiments/04_len_forgetting/prepare.py
python -m unittest discover -s experiments/04_len_forgetting/tests -v
python experiments/04_len_forgetting/train.py --selection results/len_forgetting/selections/len8_forgetting__s17.json --training-seed 17 --pilot --output outputs/len_forgetting/pilots
python experiments/04_len_forgetting/train.py --selection results/len_forgetting/selections/len8_forgetting__s17.json --training-seed 17
EXPERIMENT_PYTHON=python bash experiments/04_len_forgetting/run_all.sh
python experiments/04_len_forgetting/analyze.py
```

`train.py` поддерживает CUDA и Apple MPS. На MPS при необходимости установите `PYTORCH_ENABLE_MPS_FALLBACK=1`. Чекпойнты хранятся в игнорируемой `outputs/len_forgetting/checkpoints/`; предсказания и метрики — в `results/len_forgetting/runs/`. Проверочный `--pilot` обучается 20 шагов и оценивается на val, его результат не является результатом эксперимента. Запуск можно повторить: завершённый пропускается, незавершённый продолжается с последнего чекпойнта. Два процесса на один запуск блокируются; после завершения первый сохраняет метрики, а второй пропускает уже готовый результат. `analyze.py` проверяет метрики по отдельным предсказаниям, порядок строк и контрольные суммы подвыборок.
