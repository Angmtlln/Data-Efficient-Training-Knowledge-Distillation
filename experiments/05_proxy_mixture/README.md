# Отбор по сложности, редкости и разнообразию среди длинных фраз

## Зафиксированные до обучения гипотезы

Основной вопрос: помогает ли сознательный выбор четверти длинных фраз сверх случайного отбора при одинаковом составе по метке и длине?

1. **Умеренная сложность.** Примеры со средним для своей группы OOF-скорoм дают больше полезной информации, чем случайные, не концентрируя крайний хвост сложных случаев.
2. **Сложные vs неопределённые.** Примеры, для которых proxy назначает маленькую вероятность истинной метке (`hard`), могут вести себя иначе, чем примеры, у которых модель близка к 50/50 (`uncertainty`): первые включают уверенные ошибки proxy.
3. **Лёгкие примеры.** При бюджете 10% наиболее надёжные примеры (`easy`) могут лучше поддерживать оптимизацию, чем жёсткий отбор трудных.
4. **Лексическая редкость под контролем длины.** Возможно, редкие слова полезны, если не выбирать короткие фрагменты. Ранее отбор редких слов без ограничения длины провалился.
5. **Разнообразие групп текстов.** Выравнивание по TF-IDF-кластерам внутри групп класса и длины может улучшить покрытие без перекоса длины.

Все методы — собственные адаптации идей ниже, а не точное воспроизведение статей. Направления и параметры ниже определены до новых обучений и до просмотра результатов на внешнем датасете.

## Условия и сравнения

- SST-2 snapshot `experiments/01_cpu_selection/dataset_spec.json`, пул 65 349, val 2000, GLUE validation 872. Выбираем 6534 строки (`10%`). Фразы >=8 слов, подсчёт через `str.split`.
- Три сида 17/42/101, seed отбора = seed обучения. Протокол ModernBERT как в эксперименте 04. Модель target учится только на выбранных строках; для вычисления OOF proxy доступны метки всего пула.
- Для каждого сида: случайный общий фон 4900 строк, 1634 выбранных места (25%). Сначала случайная выборка задаёт квоты по метке и группе длины (8–11, 12–15, 16–19, 20–23, 24–27, 28–31, 32+). Все 7 вариантов содержат тот же фон и одинаковые квоты на отбираемые места.
- `mix_random`: случайные строки в каждой группе; базовый парный контроль.
- `mix_hard`: наименьшая OOF вероятность истинной метки в группе.
- `mix_uncertain`: OOF вероятность истинной метки ближе всего к 0.5 в группе.
- `mix_mid`: OOF вероятность истинной метки ближе всего к медиане группы.
- `mix_easy`: наибольшая OOF вероятность истинной метки в группе.
- `mix_rare`: максимальное среднее log IDF слов внутри группы; частоты оценены на пуле, не на тестах.
- `mix_diverse`: поочерёдная случайная выборка из непустых TF-IDF-кластеров внутри каждой группы. KMeans обучен без меток на длинных фразах пула.
- Proxy — три stratified OOF fold, TF-IDF uni/bigram + SGD log-loss, восемь эпох (настройки серии 01). Для каждого сида proxy оценивает строку, не виденную при его обучении. Сохраняем полученные массивы и контрольные суммы.
- Главные сравнения: каждое условие против `mix_random` в том же сиде; повторно используем сохранённые `random` и `len8` из серии 04 как дополнительные неизменённые baselines того же окружения.
- Никакой настройки по тесту. Различия и выбор лучшего метода на использовавшемся ранее GLUE validation — поисковые. Поправка на множественные сравнения отсутствует; финальные утверждения требуют новой независимой оценки.
- План: 21 новое полное обучение (7 условий × 3 сида); отдельно до/после сохраняем индексы, метрики и предсказания и проверяем одинаковые группы, отсутствие пересечений с фоном и хэши данных.

## Источники и применимость

- [Dataset Cartography](https://arxiv.org/abs/2009.10795): лёгкие, неоднозначные и трудные примеры могут играть разные роли; здесь используется иной, одноэтапный OOF TF-IDF-скор, а не динамика ModernBERT.
- [Selection via Proxy](https://arxiv.org/abs/1906.11829): недорогая модель может помочь выбирать данные; стоимость полного расчёта proxy и доступ ко всем меткам учитывать отдельно.
- [CCS](https://arxiv.org/abs/2210.15809): при большом сокращении набора важны покрытие и репрезентативность; TF-IDF-кластеризация здесь — другая реализация.
- [Beyond neural scaling laws](https://arxiv.org/abs/2206.14486): эффект отбора зависит от бюджета и прокси; эксперименты статьи выполнены в основном на изображениях.
- [Disentangling the Roles of Representation and Selection in Data Pruning](https://aclanthology.org/2025.acl-long.821/): отдельно важны представление текста и алгоритм отбора; здесь они не полностью разделены экспериментально.

## Внешняя проверка

Набор Rotten Tomatoes не используем для независимого теста: при предварительном аудите 706/1066 тестовых строк точно совпали после нормализации с текстами SST-2. Внешняя проверка на отзывах IMDb, если загрузка и проверка данных успешны, будет дополнительным стресс-тестом переноса на более длинные пользовательские отзывы, а не заменой SST-2 и не гарантированно независимой оценкой от предварительного обучения ModernBERT. Набор и правила отбора фиксируются до расчёта качества моделей.

## Воспроизведение

Установить зависимости из корневого `requirements.txt` и PyTorch для CUDA либо Apple MPS. Перед запуском необходимо получить и токенизировать SST-2 командами серии 04. Затем из корня репозитория:

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python experiments/05_proxy_mixture/build_scores.py
python experiments/05_proxy_mixture/prepare.py
python -m unittest discover -s experiments/05_proxy_mixture/tests -v
python experiments/05_proxy_mixture/prepare_imdb.py
EXPERIMENT_PYTHON=python bash experiments/05_proxy_mixture/run_worker.sh 0
EXPERIMENT_PYTHON=python bash experiments/05_proxy_mixture/run_worker.sh 1
python experiments/05_proxy_mixture/analyze.py
```

Две очереди распределяют 21 запуск без пересечений; их можно запустить одновременно на одной GPU либо выполнить последовательно. В режиме одной очереди для всех вариантов используйте `WORKER_COUNT=1 EXPERIMENT_PYTHON=python bash experiments/05_proxy_mixture/run_worker.sh 0`. Завершённые запуски пропускаются; незавершённые продолжаются с последнего сохранённого чекпойнта либо начинаются заново, если он ещё не был создан. Используются обучения `experiments/04_len_forgetting/train.py`. Логи и временные чекпойнты — в игнорируемой `outputs/proxy_mixture/`, сырые результаты и индексы — `results/proxy_mixture/`. После успешного завершения каждого нового обучения сохраняется только лучший модельный чекпойнт без состояния оптимизатора, чтобы экономить место. До завершения чекпойнты остаются полными и позволяют продолжить обучение.

Для IMDb после **всех 21** обучений нужен зафиксированный набор `stanfordnlp/imdb` и исходные веса baseline-моделей из `outputs/len_forgetting/checkpoints/`. Сначала проверка, затем оценка:

```bash
python experiments/05_proxy_mixture/eval_imdb.py --check-only
PYTORCH_ENABLE_MPS_FALLBACK=1 python experiments/05_proxy_mixture/eval_imdb.py
```

`prepare_imdb.py` и `eval_imdb.py` могут получать `--source` с локальной копией test split IMDb, соответствующей зафиксированному hash; иначе данные скачиваются через `datasets` по закреплённой ревизии. `analyze.py --imdb-source <путь>` проверяет внешние предсказания и метки по исходным данным. Применяется та же усечённая до 64 токенов входная длина, что и для SST-2; 1958/2000 отзывов длиннее этого порога. IMDb — иной домен, точных совпадений с SST-2 при нормализации не найдено, но полное отсутствие близких дублей или данных IMDb в pretraining не установлено.
